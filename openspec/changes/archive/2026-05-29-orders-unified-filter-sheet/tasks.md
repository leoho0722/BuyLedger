## 4. Pending selection + Apply / Cancel pattern 改造 (對應「Apply control commits pending changes and dismisses the sheet」requirement 與「Pending selection + Apply / Cancel pattern」決議)

- [x] 4.1 把 `OrderFilterSheet` 從「點選即 dispatch + dismiss」改造為「pending state + Apply 才 dispatch」pattern。可觀察行為：(a) view 新增 `@State private var pendingDatePeriod: OrderDatePeriod` 與 `@State private var pendingCategory: String?`，於 init 時以 `store.state.selectedDatePeriod` 與 `store.state.selectedCategory` 為初值；(b) 三類 row (`datePeriodRow` / `categoryClearRow` / `categoryRow`) 的 Button action 改為更新對應 pending state、**不**呼叫 `store.send(...)`、**不**呼叫 `dismiss()`；checkmark 條件改成比對 pending state；(c) toolbar 新增右上「套用」button (`.confirmationAction`)，按下時 `pendingDatePeriod != store.state.selectedDatePeriod` 才 dispatch `datePeriodSelected(pendingDatePeriod)`、`pendingCategory != store.state.selectedCategory` 才 dispatch `categoryFilterSelected(pendingCategory)`，然後 `dismiss()`；(d) 左上「取消」維持只 `dismiss()`、不 dispatch；(e) 「套用」永遠 enabled (即使無變動也 dismiss)。驗證：iOS build 通過；以 `#Preview` 觀察點選 row 後 sheet 不關、checkmark 切換正確；按「套用」後 sheet 關、按「取消」後 sheet 也關但 store state 不動 (透過 print log 或暫時 instrument 確認 dispatch 行為)。

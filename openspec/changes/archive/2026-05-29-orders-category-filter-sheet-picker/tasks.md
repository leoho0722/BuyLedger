## 1. 擴充 `OptionPickerSheet` 支援「Optional clear-selection row」

- [x] 1.1 在 `OptionPickerSheet.swift` 內新增 nested type `ClearOption { let title: String; let onClear: () -> Void }` 與 optional `clearOption: ClearOption?` 參數（預設 `nil`），對應「重用 `OptionPickerSheet` 並擴充 `clearOption`，而非新建獨立 picker 元件」決議，套用「Optional clear-selection row」requirement。可觀察行為：未傳 `clearOption` 時 picker 行為與外觀完全不變（透過既有訂單編輯流程選類別 / 付款方式 / 幣別三個 call site 手動驗證 sheet 內畫面與選取行為與本次改動前一致）；傳入 `clearOption` 時，picker 上方多一列以 `clearOption.title` 為 label 的 row。驗證：iOS / macOS build 通過；既有三個 `OptionPickerSheet` call site 不需修改即可繼續編譯與運作；以 `#Preview` 各加一組「有 clearOption」與「無 clearOption」對照觀察。

- [x] 1.2 在 iOS / iPadOS `listContent` 與 macOS `optionsCard` 中渲染 clear row 並套用 checkmark 規則，對應「`OptionPickerSheet` 內 `clearOption` row 的渲染與 checkmark 規則」決議，並完整滿足「Optional clear-selection row」requirement 中 `Empty-string selection marks the clear row`、`Tapping the clear row invokes the clear callback and dismisses`、`Clear option composes with the add control` 三則 scenario。可觀察行為：(a) clear row 位於選項列上方；當同時設 `allowsAdd: true` 時，順序為 add 按鈕 → clear row → 選項列。(b) `selected` 為空字串時 clear row 顯示 checkmark、無任何選項列 checkmark；`selected` 為某具體選項時該選項列 checkmark、clear row 無 checkmark。(c) 點擊 clear row 呼叫 `clearOption.onClear()` 並 dismiss、不呼叫 `onSelect`。驗證：在 `#Preview` 配 `selected: ""` 與 `selected: "snacks"` 兩組對照截圖檢視 checkmark 位置；以暫時 print log 或 `Logger` 確認點 clear row 走的是 `onClear` callback 而非 `onSelect`。

- [x] 1.3 在 `filteredOptions` 搜尋邏輯外保留 clear row，對應「Optional clear-selection row」requirement 中 `Search filters option rows but preserves the clear row` 與 `Search yielding no option matches still shows the clear row` 兩則 scenario。可觀察行為：搜尋輸入時 clear row 永遠顯示在最上方；搜尋有結果時 clear row 與符合的選項列共存；搜尋無結果時 clear row 仍顯示、其下為既有 `ContentUnavailableView` 空狀態。驗證：在 `#Preview` 將 `searchable: true` 開啟並輸入「不會匹配任何選項」的字串，觀察 clear row 仍呈現、下方為空狀態；輸入「會匹配部分選項」的字串，觀察 clear row 與符合的選項列共存。

- [x] 1.4 在 iOS / iPadOS `listClearRow` / `listOptionRow` 與 macOS `macClearRow` / `macOptionRow` 的 `Text` 上套 `.multilineTextAlignment(.leading) + .fixedSize(horizontal: false, vertical: true)`，並把 row 的 `HStack` 改為 `alignment: .firstTextBaseline`，套用「Option rows support multi-line text wrapping」requirement 中 `A long option label wraps to multiple lines` 與 `A long clear-row title wraps to multiple lines` 兩則 scenario。可觀察行為：長類別名稱（例如 `aespa Lemonade QQ 音樂限定禮包`）在 row 內自然換行、row 高度隨內容增長、trailing checkmark 對齊第一行 baseline；短名稱 row 視覺與舊版一致。驗證：實機 iPhone 15 Plus 開啟 sheet 觀察長類別 row 完整顯示、無 ellipsis；既有訂單編輯流程選類別 / 付款方式 / 幣別 sheet 無回歸。

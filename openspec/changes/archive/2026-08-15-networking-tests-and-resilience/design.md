## Context

網路層由四個部分組成：可注入的 HTTP 客戶端（提供緩衝與逐位元組串流兩種發送方式，以及一個組裝請求、檢查狀態碼、回傳原始資料的共用方法）、請求組裝器、錯誤列舉，以及各高階 client。匯率 client 與 AI 總結 client 都建立在其上。

錯誤列舉有六個分類，其文件註解描述了一套依分類決定是否重試的策略，但整層沒有任何重試實作。

匯率 client 的兩條路徑在網址組裝失敗時，把完整網址內插進錯誤訊息；該網址的路徑段就是 API 金鑰。取得支援幣別的路徑在回應缺少對應欄位時回傳空陣列。

幣別快取的寫入方法先刪光既有紀錄再插入新紀錄，兩者在同一次落盤內完成，但「刪光」不以「新內容非空」為前提。

AI 總結的串流只依賴請求層的逾時設定，沒有整體時長上限。

測試端已有可注入的客戶端替身機制，測試預設值一律拋出錯誤以避免意外打到真實網路，因此建立覆蓋不需要新的測試基礎設施。

## Goals / Non-Goals

**Goals:**

- 讓網路層的每一條錯誤分流都有測試釘住，使映射改動不可能靜默通過。
- 讓使用者可見的錯誤訊息不可能包含憑證。
- 讓異常回應不會摧毀本機既有的幣別資料。
- 讓串流不能無限期佔住畫面。
- 讓文件不再描述不存在的重試行為。

**Non-Goals:**

- 不實作重試。
- 不改變端點、參數或呼叫方式。
- 不改變快取有效期與更新時機。
- 不改動提示詞或串流解析格式。
- 不處理金鑰隨產物出貨的暴露面。
- 不引入模擬伺服器或第三方測試框架。

## Decisions

### 測試以既有的可注入客戶端達成，不引入模擬伺服器

高階 client 已經透過依賴取得 HTTP 客戶端，而測試預設值會拋出錯誤以防意外連網。因此只要在測試中注入回傳預備資料的替身，就能驅動所有分流。

不引入模擬伺服器：那會新增一個要維護的行程與埠號管理，換來的只是更接近真實的傳輸層，而本次要覆蓋的是分類與解碼邏輯，不是傳輸層本身。

### 錯誤訊息改為不含網址的固定字串，而非遮罩金鑰

有兩種修法：把訊息中的金鑰遮成星號，或整段不放網址。

採後者。遮罩需要知道字串中哪一段是金鑰，而那是依賴網址結構的假設；一旦端點格式改變，遮罩會失效而洩漏。不放網址則不依賴任何假設。使用者也不需要看到網址：網址組裝失敗是程式錯誤，訊息的價值在於指出發生了什麼，而非重現輸入。

### 控制字元 guard 是獨立於 Foundation 解析的前置檢查

匯率 client 在把 key 插入網址字串前，先拒絕含有控制字元的設定值，並以不含網址的固定訊息回報。這是「拒絕組裝」的宣告行為，與後續 `URL(string:)` 回傳 `nil` 的防禦性分支不同。

在目前的 Foundation 行為下，NUL 會被 `URL(string:)` 百分比編碼而不會使 URL 變成 `nil`。因此測試以 NUL 驅動的是前置控制字元 guard；後置 `URL(string:) == nil` 分支在此輸入路徑下實務不可達，保留作防禦性檢查，但不宣稱有測試覆蓋。

### 服務錯誤映射只有一份實作

`fetchLatest` 與 `fetchSupportedCodes` 共用同一個服務結果映射函式，涵蓋 invalid-key、inactive-account、quota-reached、其他 `error-type`，以及非 `success`／`error` 結果的 `unexpected-result-*` generic service error。任一 endpoint 的 mapping 變更都必須由共用測試與另一條 endpoint 路徑共同暴露。

### 快取以「取得非空結果才替換」為條件，空結果視為異常

目前的寫入是無條件的先刪後寫。改為在替換之前先判斷結果非空。

空結果不當成「服務端真的沒有任何幣別」，因為那在語意上不可能發生；它更可能是回應格式改變或欄位缺漏。因此視為異常：保留既有快取並回報，而不是把使用者的資料清掉再說。

替代作法是讓刪除與寫入拆成兩次落盤並在寫入失敗時回滾，但那既複雜又仍會在「成功寫入零筆」時清空，沒有解到根因。

### 串流加整體時長上限，逾時保留已收到的內容

請求層的逾時是閒置逾時：只要對方持續吐字就永遠不會觸發。因此需要一個獨立的整體時長上限。

逾時的處理是停止串流並保留已收到的內容，同時告知被截斷，而不是丟棄或報錯。理由是部分摘要對使用者仍有價值，而丟棄等於讓等待完全白費；專案的呈現政策要求誠實，因此必須明說被截斷。

上限值取一個明確的常數：production 固定為 30 秒，並寫進規格的驗收；測試以 `TestClock` 與 `advance(by:)` 推進這個固定上限，不另設 `DependencyValues` keyPath。

測試以同一個 `TestClock` 控制 feature 的 `\.continuousClock` 與慢速串流替身。測試透過 `advance(by:)` 明確推進 chunk 間隔與整體上限，不依賴牆鐘或 `Task.sleep`；這也避免測試環境的 `ImmediateClock` 預設值讓計時器立即獲勝。因為 `TestClock` 屬於 `Clocks` product，測試 target 明確連結該 product，避免只靠 `ComposableArchitecture` 的轉出 import 而在 linker 階段失敗。

### 文件與現況對齊的方式是刪除宣稱，而非補上實作

錯誤列舉的註解描述了一套重試策略。要對齊有兩條路：實作它，或刪掉宣稱。

本次採後者。重試需要決定退避策略、次數上限，以及對配額型錯誤的處理，那些是產品與成本決定而非技術細節；在沒有決定之前先實作等於猜。而讓註解繼續宣稱一個不存在的行為，比沒有註解更糟，因為它會讓人略過這個風險。

## Implementation Contract

**行為（使用者可觀察）**

- 網址組裝被含控制字元的 key 拒絕時，畫面上的錯誤訊息不含任何網址片段。
- Foundation `URL(string:)` 失敗 guard 保留為防禦性分支；在現行 Foundation 下實務不可達，驗收不宣稱測試覆蓋該分支。
- `fetchLatest` 與 `fetchSupportedCodes` 使用同一份服務結果映射；未預期 result 會回報 `unexpected-result-<result>`。
- `HTTPClient.send` 組出的 `URLRequest` 保留呼叫端指定的 method、headers、body 與 timeout。
- 一次回應異常導致幣別清單為空時，使用者仍能看到並選擇先前的幣別。
- AI 總結在持續緩慢輸出的情況下不會無限等待；到達上限時顯示已取得的內容並說明被截斷。
- 其餘網路行為與現況一致。

**介面與資料形狀**

- 錯誤建構點不再接受網址或設定值作為訊息內容。
- 幣別快取的替換方法以「新內容非空」為前置條件；空內容不進入刪除路徑。
- 串流的執行以整體時長上限包裹，逾時以可辨識的結果表達，而非拋出一般錯誤。

**失敗模式**

- 六種錯誤分類的邊界如規格所列，各有測試。
- `fetchSupportedCodes` 至少有一條測試驅動共用的服務錯誤映射；未預期 result 的 generic service error 也有測試與規格描述。
- 請求組裝測試從注入的 `data` 替身取出實際 `URLRequest`，斷言 method、headers、body 與 timeout。
- 空幣別結果：保留快取、回報異常，不視為成功。
- 串流逾時：保留部分內容、停止進度指示、明示截斷。
- 無自動重試：任何失敗直接回到呼叫端。

**驗收標準**

- 全專案搜尋錯誤訊息建構點，確認無任何網址或設定值內插。
- 六種錯誤分類各有至少一條測試，且刻意改動映射時對應測試轉紅。
- 解碼成功與失敗兩條路徑各有測試。
- 空幣別結果不改動既有快取，有測試斷言快取內容前後相同。
- 非空結果正確替換快取，有測試覆蓋。
- 串流在超過上限時停止並保留已收內容，有測試覆蓋。
- 錯誤列舉的註解不再描述重試策略，且明文記錄目前無重試。
- 網路層相關檔案在覆蓋率報告中由零變為非零。
- 由零變為非零的五個檔案是 `HTTPClient.swift`、`ExchangeRateClient.swift`、`ExchangeRateDTO.swift`、`URLRequestBuilder.swift` 與 `CurrencyMetadataPersistence.swift`；`OllamaClient.swift` 與 `AISummaryFeature.swift` 在本變更前已有測試，不列入此數字。

**範圍邊界**

- 在範圍內：網路層測試覆蓋、錯誤訊息的憑證洩漏、幣別快取的空結果處理、串流的整體時長上限、錯誤列舉的文件對齊。
- 不在範圍內：重試實作、端點與參數、快取有效期、提示詞與串流解析格式、金鑰隨產物出貨的暴露面、網路層檔案的位置搬移。

## Risks / Trade-offs

- [為零覆蓋區域補測試時，可能把現有的錯誤行為當成正確行為鎖住] → 每條測試先對照規格的分類表撰寫，而非對照實作；規格的分類表本身是本次新寫並經查證現況後確認合理者。
- [串流上限值設得太短會截斷正常長度的摘要] → 上限以常數表達並記入規格驗收，實作時以實際摘要長度實測後定值；逾時保留已收內容而非報錯，因此設得偏短的代價可控。
- [空結果視為異常，若服務端未來真的回空清單會被誤判] → 該情境在語意上不成立（服務不可能不支援任何幣別）；若日後真的發生，使用者看到的是舊清單而非空清單，仍可操作，屬安全的失敗方向。
- [移除註解中的重試描述後，未來仍可能有人以為有重試] → 改為明文記錄「目前無自動重試，失敗直接回到呼叫端」，比刪掉不提更能防止誤解。
- [本變更改動的錯誤訊息與匯率 client，將被金鑰暴露緩解與分層邊界整理兩案接續改動] → 依既有次序約束，本變更在前；後續兩案一為改認證方式、一為純搬檔，改動面不重疊。

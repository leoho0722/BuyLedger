## Context

本 change 從 38 項 suggestion 中挑出經評估後認定有實質必要的項目。篩選判準是「不修會怎樣」：能明確指出後果的納入，屬風格偏好或系統版本遷移的排除。

其中四項的後果最明確。分隔線內縮的數值是從頭像尺寸複製過來的字面值，而另一個已排定的 change 會把頭像改為隨字級縮放——這使得該相依在下一個 change 落地時必然顯現為視覺錯位。收鍵盤手勢以 Apple 私有型別名稱做關鍵字比對，其失效模式是靜默的：沒有編譯錯誤、沒有執行期警訊，只有使用者點擊系統文字選單時鍵盤意外收起。結團結算與篩選 sheet 的未提交變更則分別是不可逆資料變更與資料遺失，兩者在專案內都已有對應的既有規範，只是這兩處沒有遵循。

其餘納入項目分兩類：輔助技術朗讀的清理成本極低但影響每一次朗讀；零呼叫點元件與無效修飾子的刪除是純減法。

排除的項目中，色盤的 base 與 elevated 兩層合併值得特別說明：它若採用系統取色會自然解除，而該工作已排在另一個 change，因此本 change 不重複處理。

## Goals / Non-Goals

**Goals:**

- 消除會在後續 change 落地時顯現的跨檔案數值相依。
- 讓靜默失效的機制變成可被察覺的失效。
- 讓不可逆動作與未提交變更的保護在全 App 一致，不因功能模組而異。
- 清除輔助技術朗讀中的裝飾性噪音，並正確表達選取態。
- 移除零呼叫點元件與無效修飾子。

**Non-Goals:**

- 不處理其餘 19 項 suggestion。
- 不移除 App 內的語言選擇。
- 不納入三項架構重構。
- 不改動側邊欄與總覽頁的比例版面實作。

## Decisions

### 分隔線內縮與頭像尺寸抽成同源 token

四處分隔線的內縮各自手算，其中的頭像尺寸是複製過來的字面值。抽成單一 token 後，頭像尺寸與分隔線內縮由同一個來源推導，改動頭像不再需要記得同步四個地方。

更穩健的作法是以列分隔線的對齊參考線由實際頭像寬度推導，完全不需要 token。本 change 採 token 方案作為第一步，因為它改動小且能立即解除相依；對齊參考線方案在頭像改為隨字級縮放後再評估，屆時 token 的數值來源也需要隨之調整。

### 收鍵盤手勢補回歸測試，而非改寫過濾機制

以私有型別名稱比對確實脆弱，但目前沒有公開 API 能可靠識別系統文字選單。改寫過濾機制的風險高於其收益。

因此本 change 不改寫機制，而是補一個介面測試：進入文字選取狀態後點擊系統選單，斷言鍵盤不收起。這讓 iOS 改名時失效能被持續整合察覺，把靜默失效變成可見失效。同時把同時辨識的授權範圍從無條件放寬收窄為僅對已知的捲動類手勢辨識器放行。

此處的取捨是「在現行架構下」成立的。架構本身可以改變——change keyboard-dismissal-native-rewrite 已規劃把 window 級攔截換成畫面背景層的點擊，使系統文字選單落在命中測試範圍之外，從而完全不需要排除清單。本 change 建立的測試斷言的是行為而非實作，因此在該改寫後應繼續通過，並作為其驗證基準：若改寫後測試失敗，代表新機制仍在某處攔截系統選單的觸控。

### 結團結算比照既有的刪除確認實作

專案已有訂單與開團刪除的確認實作可直接比照。採用置中的警示對話框而非動作表，與專案既有規範一致——該規範的理由是動作表在較新系統版本對工具列觸發會有位置偏移。

不採用「提供取消結團」的替代方案：那會引入結算日期的可空與重算語意，屬功能變更而非合規修正。

### 篩選 sheet 的未提交變更防護比照付款方式編輯器

專案已為編輯類 sheet 建立規範：以髒值判斷阻擋下滑關閉，取消時彈出捨棄確認。篩選 sheet 的三個 pending 值與其提交後的現值比對即可得出髒值判斷。

此處的 pending 狀態目前保留在視圖本地，屬不綁 store 的可重用元件範疇，符合專案既有的例外規定，因此不需要一併下放到功能狀態。

### 列尾指示符號一律排除於無障礙樹

列尾的指示符號位於按鈕的標籤內，因此會被併入按鈕的朗讀內容，產生「類別、金額、Right chevron、按鈕」這類尾綴。按鈕特徵本身已表達可點擊，符號是純視覺提示。

一律排除而非逐處判斷：這類符號在專案內只有一種用途，沒有例外情境需要保留其朗讀。

### 採購狀態改用資訊語意色

十個訂單狀態壓進六個語意色會造成碰撞，這本身可接受——狀態膠囊一律帶文字，色彩不是唯一的區分依據。但其中採購完成被塗成警示色是語意錯配：它是正常推進的中間狀態，不是需要注意的異常。

僅調整這一個狀態的映射，不重新設計整個映射表，也不為狀態新增形狀區分——後者屬設計擴充而非修正。

### 分頁選擇的恢復以既有偏好儲存承載

重啟後回到上次分頁，可用場景儲存或既有的偏好儲存實作。採後者：專案已有偏好儲存機制，新增一個欄位比引入場景儲存的生命週期語意更簡單，且與既有的設定持久化路徑一致。

僅恢復分頁選擇，不恢復導覽堆疊與捲動位置——後者需要序列化路徑狀態，複雜度與收益不成比例。

### 空狀態改以容器相對定位置中

空狀態目前在捲動容器內以最大高度撐滿，但捲動容器在捲動軸上提供無界建議尺寸，因此該設定會塌成內容自身高度，結果是貼頂而非置中。

改以相對於容器的定位置中。專案內已有正確作法可對照，即把空狀態移出捲動容器直接掛在畫面主體上。

## Implementation Contract

#### 行為

- 按下結團結算時出現確認，說明結團後無法復原；取消則不寫入任何資料。
- 篩選 sheet 在有未提交變更時無法以下滑關閉；按取消時出現捨棄確認。
- 選項選擇器在非嵌入模式的多選情境同時提供取消與完成。
- 輔助技術朗讀列尾帶指示符號的按鈕時，不朗讀該符號；朗讀引導畫面時不朗讀裝飾插圖的符號名稱。
- 篩選列的選取項目被輔助技術與切換控制識別為已選取。
- 開團詳情的標題顯示團名；無對應開團時回退為通用名稱。
- 四處分隔線的左側內縮與頭像右緣對齊，且在頭像尺寸變更時自動維持對齊。
- 狀態膠囊與計數徽章的內距與狀態點尺寸隨系統字級縮放。
- 應用程式重新啟動後顯示上次所在的分頁。
- 刪除確認文案為主動語態且不含識別碼。
- 採購完成狀態以資訊語意色呈現，不再使用警示色。
- 捲動容器內的空狀態垂直置中於可視區域。
- 照片檢視器不設獨立關閉鈕，由宿主導覽堆疊的返回控制項離開 (推進呈現下設 ✕ 會與系統返回鍵並列冗餘；原「關閉動作位於取消位置」的設計係修正主要動作位置誤用，改由推進呈現從根本消除該誤用)。
- 文字選取狀態下點擊系統文字選單時鍵盤不收起，且該行為有測試覆蓋。

#### 介面與資料形狀

- 度量定義新增頭像尺寸與分隔線內縮兩個 token，後者由前者推導。
- 開團功能狀態新增結團確認的警示狀態。
- 偏好儲存新增分頁選擇欄位。
- 選項選擇器的多選分支在非嵌入模式提供取消動作。
- 移除三個目標：清單列元件、金額輸入欄元件、以及排版修飾子中的無效字距設定。
- 收鍵盤手勢的同時辨識判斷改為僅對已知的捲動類辨識器回傳可同時辨識。

#### 失敗模式

- 分隔線 token 抽取後，若某處仍保留原本的手算式，該處會在頭像尺寸變更時錯開而其他三處正確，反而更難察覺。
- 偏好儲存新增欄位時，若序列化對未知欄位容錯不足，既有安裝的其他偏好會被重置。
- 收鍵盤手勢的同時辨識範圍收窄後，若遺漏某個必要的捲動辨識器，該處捲動時鍵盤不會收起。
- 空狀態改以容器相對定位後，若該容器本身高度不確定，置中會失效而回到貼頂。

#### 驗收標準

- 實機確認結團結算出現確認且取消不寫入；篩選 sheet 有未提交變更時無法下滑關閉且取消會確認。
- 實機以輔助技術逐一確認：列尾符號不被朗讀、引導插圖不被朗讀、篩選列選取態被識別。
- 實機確認開團詳情標題顯示團名；四處分隔線與頭像右緣對齊；空狀態垂直置中。
- 實機於最大無障礙字級確認狀態膠囊與計數徽章的內距隨字級擴大且文字未被擠壓。
- 實機重啟應用程式確認回到上次分頁；並以既有偏好資料啟動確認其他設定未被重置。
- 新增的介面測試涵蓋「文字選取後點擊系統選單不收鍵盤」並通過。
- 全專案搜尋不到已刪除的兩個元件型別；iOS 與 iPadOS 皆建置成功。
- 既有單元測試全數通過；snapshot baseline 重錄後差異僅限預期範圍。
- 字串目錄的中英完整性測試通過。

#### 範圍邊界

**在範圍內：** 結團確認；篩選 sheet 未提交變更防護；選項選擇器取消動作；列尾符號與裝飾插圖的朗讀排除；篩選列選取態；開團詳情標題；分隔線 token；膠囊內距隨字級；分頁恢復；刪除文案；採購狀態語意色；空狀態置中；照片檢視器離開動作；收鍵盤手勢的回歸測試與辨識範圍收窄；三個目標的刪除。

**在範圍外：** 其餘 19 項 suggestion；App 內語言選擇；三項架構重構；側邊欄與總覽頁的比例版面；色盤 base 與 elevated 兩層的合併。

## Risks / Trade-offs

- [分隔線 token 抽取若有遺漏，錯位會在頭像改為隨字級縮放時才顯現，屆時已跨 change 難以歸因] → 抽取後全專案搜尋原本的手算式確認無殘留，並在 dynamic-type-and-grouping 的頭像任務中一併目視確認四處對齊。
- [收鍵盤手勢維持私有型別名稱比對，僅補測試而未改寫機制] → 這是刻意的取捨：目前沒有公開 API 能可靠識別系統文字選單，改寫的風險高於收益。測試把靜默失效變成可見失效，已達成本 change 的目標；若日後出現公開 API 再行改寫。
- [偏好儲存新增分頁欄位可能影響既有安裝的其他偏好] → 新增前確認序列化方式對未知與缺失欄位的容錯行為，並以既有偏好資料實測啟動。
- [採購狀態改色會改變使用者已熟悉的視覺] → 此變更修正的是語意錯配，改後與其他推進中狀態同色，反而更符合使用者對「進行中」的預期。
- [本 change 項目多而分散，容易在實作中漏項] → 任務依主題分組且每項各自有明確的驗證方式；驗收時逐項對照 Implementation Contract 的行為清單。

## Context

本 change 收斂審查中觸控與輸入領域的八項 warning。它們分屬三個不同的根源，但共通點是缺陷不會在目視檢查中暴露：命中區不足看起來正常只是點不太到、手勢無替代對慣用直接觸控的人完全無感、輸入缺陷只在實際連續輸入時才顯現。

命中區的契約由 hig-blocker-remediation 建立並涵蓋兩個 blocker 級控制項，本 change 將同一契約套用到其餘八處。六處篩選膠囊的實作彼此複製貼上，若逐處修補會留下六份仍可能再度分歧的程式碼。

輸入方面，訂單編輯表單有十個數值欄位，而數字鍵盤沒有 return 鍵。目前唯一的收鍵盤途徑是全域點擊手勢，但在密集排列的表單中使用者容易點到相鄰欄位而非空白處。

照片檢視器目前只實作橫向換頁。加入縮放後兩種手勢會在同一個容器上競爭，需要明確的接手規則。

## Goals / Non-Goals

**Goals:**

- 讓六處重複的篩選膠囊收斂為單一元件，使命中區這類契約只需在一處維護。
- 所有靠手勢觸達的功能都有可見的按鈕或選單替代。
- 訂單編輯表單具備完整的鍵盤操作路徑：可收鍵盤、可跳欄位、欄位可靠地被點中。
- 照片檢視器遵循系統的標準手勢語彙。

**Non-Goals:**

- 不處理 blocker 與 suggestion 等級的發現。
- 不新增觸覺回饋。
- 不改動收鍵盤的全域手勢實作。
- 不調整篩選膠囊的視覺設計。
- 不為照片檢視器新增縮放與換頁以外的互動。

## Decisions

### 六處篩選膠囊抽成共用元件而非逐處修補

六處膠囊的實作是彼此複製的產物，內距與字級各有小差異但結構相同。逐處補上命中區會留下六份仍會再度分歧的程式碼，而且下一個新增的膠囊仍會從既有的錯誤版本複製。

抽成共用元件後，命中區、內距與選取態的表達只需維護一處。元件參數以現有六處的用法為準，不新增未被使用的彈性。

### 命中區加在標籤內部並以形狀宣告涵蓋整個膠囊

與 hig-blocker-remediation 相同的判準：外層容器的內距只增加版面間距、不擴大控制項自身的命中區。膠囊為圓角形狀，形狀宣告需涵蓋整個膠囊而非其外接矩形，以免相鄰膠囊的命中區重疊。

### 手勢的可見替代放在既有的操作選單內，不新增獨立控制項

開團詳情已有操作選單，商品明細已有可見的新增入口。刪除的替代入口應放進這些既有位置，而非新增獨立按鈕——後者會增加版面負擔且與既有的資訊架構不一致。

商品明細採用系統清單的編輯模式提供刪除入口，與新增按鈕形成對稱的可見入口。

### 鍵盤工具列採系統標準工具列而非自製配件視圖

系統標準工具列在較新的系統版本上會自動採用系統材質，且其擺位與安全區處理由系統負責。自製配件視圖需要自行處理這些，且無法取得系統的視覺演進。

工具列只放「完成」一個動作。不加入上一欄與下一欄的箭頭，因為焦點順序的跳轉已由焦點管理提供，重複的入口會增加工具列的視覺負擔。

### 焦點狀態放在功能狀態而非視圖本地狀態

專案既有慣例是綁定 store 的視圖不持有呈現狀態。焦點是呈現狀態的一種，因此焦點欄位放在功能狀態中，由視圖以綁定連結。這也讓「新訂單時聚焦第一個欄位」這件事可以在 reducer 中表達並被測試涵蓋，而不是散落在視圖的生命週期回呼裡。

### 照片縮放以縮放倍率決定換頁是否接手

縮放與換頁在同一個容器上競爭手勢。規則是：倍率為一時換頁接手、倍率大於一時改為平移而換頁停用。這與系統照片瀏覽的行為一致，使用者不需要學新規則。

雙點在一倍與兩倍之間切換，而非逐級放大，避免使用者需要多次雙點才能回到原始尺寸。

## Implementation Contract

#### 行為

- 六處篩選膠囊與開團收款狀態切換鈕的命中區各方向不小於 44pt，視覺尺寸與變更前一致，且相鄰膠囊的命中區不重疊。
- 開團可從詳情頁的操作選單刪除，不需長按列表列；商品明細可從可見入口刪除，不需左滑。
- 客戶名稱欄位在系統有可用聯絡人資料時提供填入建議。
- 使用數字鍵盤的表單在鍵盤上方顯示完成按鈕，按下即收起鍵盤；表單亦可透過捲動收起鍵盤。
- 訂單編輯表單的數值欄位命中高度不小於 44pt，點在該列的上下緣即可聚焦該欄位。
- 開啟新訂單時第一個欄位自動聚焦；欄位之間可依視覺順序跳轉。
- 照片檢視器支援縮放與雙點放大；倍率為一時左右滑動換頁，倍率大於一時左右滑動改為平移。

#### 介面與資料形狀

- 新增共用篩選膠囊元件，其參數涵蓋標題、選取狀態與點擊動作，不提供目前六處用法以外的彈性。
- 訂單編輯功能狀態新增可選的焦點欄位，其型別為可雜湊的欄位列舉，依視覺順序定義。
- 照片檢視器內部維護縮放倍率與平移位移，兩者皆不對外暴露。

#### 失敗模式

- 命中區擴大後若形狀宣告使用外接矩形而非膠囊形狀，相鄰膠囊的命中區會重疊，導致點擊落在錯誤的膠囊上。
- 焦點狀態若在 sheet 關閉時未清除，下次開啟表單會沿用上次的焦點欄位並意外彈出鍵盤。
- 縮放中若未停用換頁，平移手勢會被換頁攔截，使用者無法檢視放大後的照片邊緣。
- 鍵盤工具列若掛在錯誤的層級，會在非數字鍵盤的欄位上也出現。

#### 驗收標準

- 實機以 Accessibility Inspector 量測六處篩選膠囊與收款切換鈕的命中區皆不小於 44×44pt，並確認相鄰膠囊各自可獨立點中。
- 實機以語音控制或切換控制執行刪除開團與刪除商品明細，確認不依賴手勢即可完成。
- 實機確認客戶名稱欄位出現填入建議；確認數字鍵盤上方有完成按鈕且可收起鍵盤；確認捲動亦可收鍵盤。
- 實機確認開啟新訂單時第一個欄位聚焦，且可在欄位間跳轉。
- 實機確認照片可縮放、雙點可在一倍與兩倍間切換、放大後可平移且不會誤觸換頁。
- 以 TestStore 撰寫的焦點相關測試通過；既有單元測試全數通過。
- 字串目錄的中英完整性測試通過。

#### 範圍邊界

**在範圍內：** 六處篩選膠囊的元件化與命中區；收款切換鈕命中區；開團與商品明細的可見刪除入口；欄位內容型別；鍵盤工具列與捲動收鍵盤；表單數值欄位命中區；訂單編輯的焦點管理；照片檢視器的縮放與雙點。

**在範圍外：** blocker 與 suggestion 等級的發現；觸覺回饋；收鍵盤的全域手勢實作；篩選膠囊的視覺設計；照片檢視器的其他互動。

## Risks / Trade-offs

- [六處膠囊抽成共用元件時，若元件參數未涵蓋某處的既有差異，該處會出現非預期的視覺變化] → 抽取前先逐處記錄現有的內距與字級差異，並在元件中以參數或預設值保留；抽取後以 snapshot 比對六處的視覺結果。
- [焦點管理導入後，新訂單自動聚焦會使鍵盤在 sheet 開啟時立即彈出，可能遮蔽表單上半部] → 驗收時確認聚焦後的捲動位置使第一個欄位可見；若體感不佳，改為不自動聚焦而僅保留跳轉能力，並記錄該取捨。
- [縮放與換頁的手勢競爭若規則實作有誤，會使換頁或平移其中之一失效] → 以倍率為唯一判準，並在實機分別驗證倍率為一與大於一時的兩種行為。
- [商品明細改用系統編輯模式提供刪除入口，會改變該區塊的既有互動] → 保留既有的左滑刪除，新入口為增加而非取代，使既有使用者的操作習慣不受影響。
